# 影悦 · 独立版 (CinemaJoy) 软件工程宪章 (Constitution)

## Core Principles (核心开发准则)

### I. 规范先于实现 (Spec-Driven Development)
- **非协商性准则**：任何功能开发或非简单修复，严禁在未确立明确规范（Specification）与任务清单（Tasks）的情况下直接改写代码。
- **流程闭环**：
  1. **明确定义**：厘清输入、输出、边界条件与验收标准（Acceptance Criteria）。
  2. **方案架构**：拆解模块依赖，评估对现有核心逻辑（媒体接口、DNS 防污染、海报自愈、GPU 解码）的影响面。
  3. **细化任务**：将工程拆解为可独立验证的原子步骤（Atomic Steps）。
  4. **精准实施**：按任务清单逐步执行，每步均有明确的通过标志。

### II. 极致 Token 节约与上下文轻量化 (Token Economy)
- **局部精修优先**：首选精确定位并使用 `edit_file` 替换最小代码块，严禁全量重写非必要大文件。
- **信息密度最大化**：杜绝寒暄客套、重复背景叙述与发散性讨论，以可执行命令、代码与客观状态为第一输出。
- **上下文按需加载**：严禁无序通读整库文件，善用 AST 结构与针对性检索，确保长周期会话不溢出。

### III. 原版纯净与第三方注解隔离 (Vanilla Code Standard)
- **品牌与代码纯粹性**：应用标识严格保持为「影悦」(CinemaJoy)。
- **严禁外部产品注解**：代码、注释、文档及命名严禁引入外部商业竞品或第三方软件产品名（如微看、TVBox、苹果CMS、当贝等），统一规范为「标准通用媒体采集 JSON 接口」与「通用影视源订阅配置」。

### IV. 测试驱动与零回归验证 (Test-First & Zero Regression)
- **测试前置**：核心逻辑变更必须有对应的断言与测试覆盖。
- **全绿交付**：任何修改必须通过 `npm test`（11 项技术模块与端侧 AI 自动化测试），严禁带崩已有功能。

## Governance (治理与强制执行)

- 本宪章为本项目最高开发准则。
- AI 编码助手在本项目内的所有后续开发、重构、修障工作，均需严格遵循本宪章之规范。
